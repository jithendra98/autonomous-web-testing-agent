AI Agent Developer Architecture Briefing

Autonomous web agent architecture, ReAct reasoning, perception, and self-healing error recovery.

AI Agent Developer: Mallela Jithendra

1. The Core Engineering Problem for Web Agents

Modern single-page applications dynamically hash CSS class names on each deployment, rendering traditional locators brittle. At the same time, feeding raw HTML to LLMs wastes 40,000+ characters of non-interactive wrapper tags, causing high latency and runaway token bills.

2. What I Engineered

• Accessibility-Tree DOM Pruner: Injected JS evaluator filtering non-interactive nodes, cutting token overhead by 88.6% while retaining 100% interactable reachability.
• 4-Tier Self-Healing Engine: When dynamic CSS breaks, cascades through ARIA labels (`get_by_label`), role+name semantics (`get_by_role`), inner text, and spatial bounding box coordinates via CDP mouse clicks.
• CDP Telemetry: Directly captures V8 console errors, HTTP 4xx/5xx failures, and full-page screenshots into audit-grade reports.

3. Key Technical Challenge Solved

Dynamic Class Hashing Recovery: In our live testbench, the portal intentionally mutates CSS button classes mid-session. Our locator automatically detects the failure and resolves the target via Tier 1 ARIA semantics, achieving a 92.5% recovery rate across mutated application states with zero human intervention.
