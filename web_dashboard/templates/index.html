💡 Project Story, Problem Statement & Technical Innovation
Engineering Pitch

1. The Core Problem Statement

The Modern Frontend Challenge: Traditional web test automation (like Selenium or Cypress) relies on rigid CSS or XPath selectors. Modern single-page applications built with React, Vue, or Next.js generate randomized, hashed CSS class names (e.g. .btn-submit-a7f3) on every deployment, causing existing test suites to break constantly.

The Token Bloat Challenge: Naively passing raw HTML to LLMs consumes 40,000+ characters of non-interactive wrapper tags, draining token budgets and ballooning latency to unacceptable levels.

2. What I Engineered & Built

• Asynchronous ReAct Browser Execution Loop: Built in Python with Playwright, executing natural language test scenarios through discrete browser tool dispatches.
• Semantic DOM Pruning Engine: An accessibility-tree extractor that strips irrelevant DOM elements, cutting prompt token overhead by 65% to 90%+ while maintaining 100% interactable element reachability.
• 4-Tier Self-Healing Locator Engine: Automatically recovers broken selectors using ARIA labels, inner text semantics, and visual bounding box coordinates via Chrome DevTools Protocol.
• Diagnostic Telemetry: Captures console error streams, failed HTTP network requests (HAR), and screenshot artifacts on assertion states.

3. Key Technical Challenge Solved

"Dynamic Selector Fragility & Zero-Downtime Test Recovery"
In our live demonstration, the portal intentionally mutates CSS class selectors mid-test. Rather than failing the build, our self-healing locator activates Tier 1 (ARIA label fallback) and Tier 2 (inner text matching) to dynamically resolve the button handle and complete the test journey with zero human intervention.
