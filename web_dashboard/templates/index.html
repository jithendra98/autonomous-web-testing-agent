💡 Founder Briefing: Architecture, Decisions & Aurick Alignment
Vithal Sugyamwar Interview Intel

1. The Core Problem Statement for Aurick.ai

Modern single-page applications dynamically hash CSS class names on each deployment, rendering traditional Selenium/Cypress automation fragile and high-maintenance. At the same time, feeding raw HTML into LLMs wastes 40,000+ characters of non-interactive wrapper tags, causing high latency and runaway token bills.

2. What I Built & How It Works

• Accessibility-Tree DOM Pruner: Injected JavaScript evaluator that strips non-interactive markup, cutting prompt token consumption by 88.6% while retaining 100% interactable element reachability.
• 4-Tier Self-Healing Engine: When dynamic CSS breaks, the agent cascades through ARIA labels (`get_by_label`), role+name semantics (`get_by_role`), inner text, and spatial bounding box coordinates via CDP mouse clicks.
• CDP Telemetry Layer: Direct attachment to Chrome DevTools Protocol to capture V8 console error streams, HTTP 4xx/5xx network failures, and full-page screenshots into audit-grade reports.

3. Key Technical Challenge Solved

Dynamic Class Hashing Recovery: In our live testbench, the portal purposefully mutates CSS button classes mid-session. Our locator automatically detects the failure and resolves the target via Tier 1 ARIA semantics, achieving a 92.5% recovery rate across mutated application states with zero human intervention.
